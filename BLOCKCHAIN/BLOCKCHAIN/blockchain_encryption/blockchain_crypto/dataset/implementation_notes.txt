## CryptoChain - Blockchain File Encryption System
Date: August 19, 2026

### System Architecture

The CryptoChain system is built on the following stack:
- Backend: Python Flask
- Encryption: AES-256 (Fernet)
- Key Derivation: PBKDF2-SHA256 (100,000 iterations)
- Hashing: SHA-256
- Blockchain: Proof of Work consensus
- Frontend: HTML5, CSS3, JavaScript

### Database Structure

Users Table:
- user_id (PRIMARY KEY)
- username (UNIQUE)
- email (UNIQUE)
- password_hash (PBKDF2)
- created_date
- last_login

Files Table:
- file_id (PRIMARY KEY)
- user_id (FOREIGN KEY)
- original_filename
- file_hash (SHA-256)
- encrypted_hash (SHA-256)
- file_size
- created_date
- encryption_status

Blockchain Table:
- block_id (PRIMARY KEY)
- block_index
- previous_hash
- transaction_hash
- nonce
- timestamp

### API Endpoints

POST /api/encrypt
- Upload file for encryption
- Returns: file_id, download_url

POST /api/decrypt
- Upload encrypted file for decryption
- Returns: decrypted file

GET /api/blockchain
- Returns all blocks in chain

GET /api/blockchain/verify
- Verifies blockchain integrity

GET /api/download-encrypted/<file_id>
- Downloads encrypted file

### Security Considerations

1. Password Requirements:
   - Minimum 8 characters recommended
   - Mix of uppercase and lowercase
   - Include numbers and special characters

2. File Integrity:
   - All files are hashed with SHA-256
   - Hashes stored in blockchain
   - Users can verify integrity at any time

3. Encryption Parameters:
   - Salt: 16 bytes (random)
   - PBKDF2 Iterations: 100,000
   - Key Derivation: SHA-256
   - Encryption: AES-256-CBC
